# Support

Use the test GitHub Project and test Linear project for planned acceptance work. Use the exact repository's issue tracker for reproducible defects, blocked readiness, and evidence gaps.

When reporting a problem, include the tested repository and immutable revision, workflow run, browser or worker profile, expected contract, observed result, and whether required upstream artifacts, credentials, capacity, or network paths were available. Do not include secrets, customer data, production test data, private repository inventories, or incident details.

A missing environment, dependency, credential, or authorization is blocked readiness. It is not a passing result and should not be labeled a product regression without evidence.
